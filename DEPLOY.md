# Deploy the API (free tier)

Stack: **GitHub Actions** → **Render** (Docker web service) + **Neon** (Postgres) + **Cloudflare R2** (files and JSON backups). The web app is a separate repo; see `erp-frontend/DEPLOY.md`.

Free-tier limits change. Confirm current quotas at signup. Render free sleeps after idle; Neon free suspends the compute. The hourly GitHub cron wakes both.

## 0. GitHub repo

```bash
cd erp-backend
git remote add origin git@github.com:<org>/erp-backend.git   # or HTTPS
git push -u origin master   # or rename to main first
```

CI (`.github/workflows/ci.yml`) runs tests and builds the Docker image on every push. It does not deploy.

## 1. Neon Postgres

1. Create a project in [Neon](https://console.neon.tech) (region close to Singapore if you can; otherwise the nearest).
2. Create a database named `erp` (or keep `neondb` and use that name in the URLs).
3. Copy **two** connection strings from the dashboard:
   - **Pooled** (has `-pooler` in the host) → `DATABASE_URL`
   - **Direct** (unpooled) → `DIRECT_URL`
4. Append query params:

```
DATABASE_URL=postgresql://USER:PASSWORD@ep-….pooler.….neon.tech/erp?sslmode=require&pgbouncer=true&connection_limit=5
DIRECT_URL=postgresql://USER:PASSWORD@ep-….….neon.tech/erp?sslmode=require
```

Prisma migrations must use `DIRECT_URL`. The API uses the pooled `DATABASE_URL` at runtime.

Optional: create a Neon **branch** named `staging` for experiments. One Render free service can only point at one database at a time, so treat the first deploy as staging until UAT sign-off, then point it at the production branch (or a second Neon project).

## 2. Cloudflare R2

1. R2 → Create bucket `erp-files`.
2. Object lifecycle (optional): prefix `backups/` expire after 30 days. The API already drops snapshots from its index after `BACKUP_RETENTION` (default 14).
3. Manage R2 API Tokens → create a token with **Object Read & Write** on that bucket.
4. Note:
   - Endpoint: `https://<account-id>.r2.cloudflarestorage.com`
   - Access key ID and secret access key

## 3. Render API

1. [Render](https://dashboard.render.com) → New → **Blueprint**.
2. Connect `erp-backend` and apply `render.yaml` (service name `erp-api`, Singapore, free Docker).
3. Fill the `sync: false` env vars:

| Variable | Value |
| --- | --- |
| `DATABASE_URL` | Neon pooled URI |
| `DIRECT_URL` | Neon unpooled URI |
| `CORS_ORIGINS` | Web origins, comma-separated, **no trailing slash**. Example: `https://erp-web.pages.dev` |
| `PUBLIC_API_URL` | This service’s public origin, e.g. `https://erp-api.onrender.com` |
| `S3_ENDPOINT` | R2 endpoint |
| `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` | R2 token |
| `SEED_ADMIN_EMAIL` | First admin, e.g. `admin@yourcompany.com` |
| `SEED_ADMIN_PASSWORD` | Min 8 characters. Used **only** if that user does not exist yet |

`JWT_*_SECRET` and `CRON_SECRET` are generated by the blueprint. Copy `CRON_SECRET` for GitHub.

On first boot the container runs `prisma migrate deploy`, the idempotent **base** seed (roles, chart of accounts, space presets, admin user), then the API. It does **not** load demo catalog data.

Health check: `GET /health` (DB ping). First boot can take a minute while Neon wakes.

## 4. Hourly jobs + nightly backup

In the **GitHub repo** Settings → Secrets:

| Secret | Value |
| --- | --- |
| `API_URL` | Same as `PUBLIC_API_URL` (no trailing slash) |
| `CRON_SECRET` | Same as Render `CRON_SECRET` |

`.github/workflows/cron.yml` `POST`s `/api/v1/system/jobs` every hour. That wakes Render, sends overdue/expiry/low-stock notices, expires old quotations, and once per night writes a gzip JSON snapshot to R2 (`backups/…`). Admins can also create and download snapshots from **Settings → Data** (Backups).

These snapshots complement Neon’s restore window. They are not a `pg_dump`.

## 5. Smoke the live API

```bash
curl -sf https://erp-api.onrender.com/health
# open https://erp-api.onrender.com/docs
```

Log in with `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD`, then change the password.

If the first request after idle returns 502/503, wait 30–60 seconds and retry (Render cold start).

## 6. CORS handshake

After Cloudflare Pages has a URL, set Render `CORS_ORIGINS` to that origin (and any custom domain). Redeploy is not required for env changes on Render; the service restarts.

## Troubleshooting

| Symptom | Likely cause |
| --- | --- |
| Deploy crash-loop: `SEED_ADMIN_PASSWORD is required` | First boot, admin does not exist, password env missing |
| `prepared statement` / migrate lock errors | `DATABASE_URL` is pooled without `DIRECT_URL` unpooled |
| CORS errors in the browser | `CORS_ORIGINS` missing the Pages origin, or a trailing slash |
| Files/PDF/photos fail | R2 token, bucket name, or `S3_ENDPOINT` |
| Jobs never run while idle | GitHub `API_URL` / `CRON_SECRET` secrets not set |
| `/health` 503 on first hit | Neon or Render was asleep; retry |

## Staging vs production (free)

One Render free web service. Recommended path: deploy this as **staging**, UAT with the client, then either keep it as production or create a second Neon database and switch `DATABASE_URL` / `DIRECT_URL` after a final snapshot.
